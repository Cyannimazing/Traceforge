## Independent implementation

`topHolderCohort` selects 50 raw EVM accounts or 20 raw Solana owners by measured supply share, with deterministic address tie-breaking, then separates independently attributed infrastructure and independently verified EVM code contracts. It retains EIP-7702 delegated EOAs. It selects the first 15 remaining rows before filtering creators or unread activity. No addresses, target holder count, token-specific coefficient or imported Swarm value enters this policy.

EVM code exclusion requires structured account type and raw bytecode from the existing activity reader, the same pinned block reference as its freshly observed finalized snapshot, a matching available RPC source and an independently bound current token balance matching the reported share. Missing, stale, malformed, unbound or reorg-invalidated proof cannot hide a holder. A changed or unverifiable anchor discards both code and nonce proofs. A later provider deadline preserves already completed code proofs when the anchor still agrees. These fields reuse existing RPC calls; no additional provider scans or concurrency were added.

The helper returns contract and infrastructure partitions separately and an explicit float basis. Float retains all measured current infrastructure, including known accounts below the raw assessment cap, and still becomes unavailable when a required current pool balance is missing. Selected generic code contracts are an additional, separately described assessment set-aside. This cautious denominator behavior is retained even though the public corpus does not establish Swarm's treatment of infrastructure outside its raw cap.

The full holder inventory, holding proofs, global strict score bounds and full relationship risk checks remain intact. A connected group outside the raw top 50 can still impose the existing score cap; critical controls still override the selected-cohort model. Both supported observed models use the first 15 activity candidates without backfill. Solana's complete lifetime-fresh predicate remains unproven by short signature pages. The saved Grok case still calculates 87 and decision weight .801.

All conditional exposure factors use selected current holdings and the same cohort denominator. `buildScoringInputs` accepts an explicit exposure scope for insider, sniper and creator-linked fractions while retaining the original full identity, receipt, verified timing and funding evidence. Its default strict calculation continues to use the entire snapshot. A one-percent creator-funded holder below raw Solana rank 20 changes the full strict exposure but leaves the selected point factors and score unchanged; a verified sniper below raw EVM rank 50 likewise remains in strict exposure without entering the selected point fraction. This fixes a mixed-scope calculation discovered during review.

Persisted report cache schema is 16 so old reports without structured code proof and the new cohort interpretation are not silently reused. Existing saved captures are not mutated to invent missing proof; a new live scan is needed for end-to-end production validation.
